Direction · the breadth flywheel

Breadth that writes itself.

Hand-build a universal core to extract the contract — then build the machine that authors the rest. Connectors are the unit of breadth, so the endgame is making authoring one a near-zero-cost, agent-driven act against a clean contract. Then any source becomes agent-queryable context on demand. The connectors are generated; the trust machinery that makes generation safe is the product.

STATUS: adopted as the eventual flywheel. V0 hand-builds the universal core and extracts the SDK from it; agent-authoring is proven next, and the self-serve sandbox comes last (see the beta roadmap).
00  The thesis

The product is a connector-authoring platform. The gateway is its runtime.

The original framing was "a gateway with connectors," where breadth grows one hand-built adapter at a time — slow, and not differentiated (anyone can hand-write adapters). The sharper framing: the connector is the unit of extension, so make authoring one trivial and agent-driven, and breadth becomes self-serve and unbounded.

This is the logical endpoint of "everything is a connector." If the contract is clean enough that an agent can author a connector from API docs + the SDK, you stop building integrations and start building the thing that builds integrations. That's a different, more defensible company: the place where any source becomes agent-queryable personal context — and the catalog writes itself.

Why this is the wedge

Every competitor is either a single vertical (one source family, deep) or a notes-only memory store (no real account connectors). A platform whose breadth writes itself is the one thing neither can match without rebuilding their core — and it's the direct payoff of the SDK-first architecture.

01  Why agents are good at exactly this

Code against a spec is peak agent. Web automation is not.

Authoring a connector is writing three functions — sync, normalize, strongKeys — against a narrow, documented, testable interface, mapping a source's API into a fixed schema. This is the single thing modern agents are most reliable at: bounded code generation against a clear contract with a feedback signal (tests). It is not the brittle, side-effectful, long-horizon web automation that "Part A" (autonomous account creation) would require — see §06.

// the entire authoring target — three functions against one interface
interface Connector<TNormalized> {
  sync(ctx): AsyncIterable<RawRecord>;        // pull from the source's API since a cursor
  normalize(raw): TNormalized;                // map → the sector's standard schema
  strongKeys(raw): Record<string, string>;    // deterministic keys
}

The guardrails that turn "an agent wrote it" into "and it's safe to run"

03  Where the moat actually is

Not the connectors. Not the SDK. The trust machinery.

layerwho owns itwhy
The connectorsgeneratedCommodity — an agent writes them. No defensibility in the artifact.
The SDK + schema contractApache / openOpen on purpose, to maximize who can author. Not a moat by itself.
The sandboxownedMakes running generated code safe (no ambient secrets, egress-limited, capped). Hard to build, the whole reason to trust it.
The conformance harnessownedMakes generated code correct & uniform (schema-valid, idempotent, auth-safe). The quality gate nobody else has bothered to build.
The one-line version

Generation is cheap; everyone has the same frontier model. Trustworthy generation — safe to run, correct against a schema, uniform across hundreds of sources — is not. That layer is the owned, defensible product.

04  Getting here — extract, then automate

Hand-build the core. Extract the SDK. Then let agents author.

You can't design a good connector SDK in a vacuum — you extract it from a few real connectors, then automate. So V0 hand-builds the universal core (agent-assisted, reviewed); that crystallizes the SDK + conformance harness; then an agent authors against the hardened contract; and only when authoring opens to users do you build the sandbox.

  1. Hand-build the core (V0). Finance, the Outlook + Gmail bundles, Whoop, Home Assistant — agent-assisted and reviewed. The variety of API shapes is the point: it's what a good contract has to cover.
  2. Extract the SDK + conformance harness. From those real connectors, crystallize the @pci/sdk Connector interface + normalized schemas, and a harness that asserts schema-valid rows, idempotency, pagination, and auth refresh. The harness is the IP.
  3. Prove agent-authoring. Hand an agent the now-hardened SDK + a new source's API docs; it authors the connector; you review; it passes the harness. The thesis, proven cheaply — on a battle-tested contract.
  4. Build the sandbox. Only now — because only now does untrusted, user-triggered generated code run: a constrained executor with scoped token, egress allowlist, no ambient secrets, and caps.
  5. Open the self-serve loop. "Connect X" → agent authors → sandbox + conform → review → live. The sharing/review tier turns generated connectors into the open ecosystem.
The milestone that matters

V0 ships at steps 1–2 (a real gateway over the hand-built core). The thesis milestone is step 3: "an agent wrote a connector — we didn't — against our extracted SDK, and it passed conformance and pulled real data." That's the proof, and the demo.

05  Risks, eyes open

The honest costs of going meta-first.

riskmitigation
Framework-in-a-vacuum. Over-polishing the abstraction before a real connector validates it.The extract-then-automate order is the mitigation: hand-build real connectors first and extract the SDK from them — never design the abstraction up front. The harness is only "done" when a connector passes against real data.
The sandbox is real work — but deferred. Running untrusted generated code safely is non-trivial; it's the cost of opening authoring to users.It lands in Phase 3 (self-serve), not at V0 — your own reviewed connectors don't need it. Lean on an existing isolation primitive (locked-down container / WASM / microVM); buy the isolation, own the policy.
API quality varies. Clean docs → great; undocumented/scraped → brittle.Pick a clean-API source first (Whoop, Home Assistant) so the thesis test isn't confounded. Tier sources by API quality.
Complexity creep. This is more ambitious than the de-escalated simple gateway.It's the right complexity if "breadth writes itself" is the bet. Keep the first slice narrow (one sector, one source) so it stays shippable.
06  Parked: Part A — autonomous web onboarding

Why "agent makes the dev account & reads the OTP" is not in this plan.

The sibling idea — an agent driving a browser to create a developer account, read the email OTP, mint tokens, and self-onboard — is deferred deliberately. It is a different, far riskier capability than authoring code:

  • The sources that matter are gated. Plaid requires an approved company application; Google sensitive scopes (Gmail) require app verification (weeks, security review). No agent clicks past those. Auto-onboarding only works on permissive, ungated APIs.
  • It inverts the security model. It needs an agent with email access + a logged-in browser + credential-creation power — by construction, account-takeover capability. Reading OTP emails / web pages is also the prime prompt-injection surface. That contradicts the "minimal, scoped, auditable custodian" identity.
  • ToS + reputation. Auto-creating accounts and accepting developer agreements violates many providers' terms, and "read the OTP and finish the flow" is the bot-takeover signature. A trusted custodian can't also be the bot farm hitting everyone's dev portals.
  • Brittleness. Long web flows break constantly (≈0.95^20 ≈ 36% success on a 20-step flow).
The responsible version, if revisited

Solve the underlying dev-app friction with a hosted OAuth broker (pre-register the platform apps once → one-click consent). And if an agent assists onboarding, make it supervised: the agent drafts and pre-fills, a human approves the consequential steps (account creation, ToS, scope grants). Agent does the tedious 90%; a person owns the binding 10%.

Build the machine that authors connectors. Own the part that makes generation trustworthy.
