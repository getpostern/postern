# ADR 0029 — The MCP OAuth bridge: a minimal same-origin AS wrapping the static agent key (opt-in, default off)

**Status:** Accepted — **SHIPPED and DEPLOYED** (merge record 2026-07-17; `src/mcp/oauth-bridge.ts` + migration `0014_oauth_bridge_and_key_expiry.sql`; deployed 2026-07-17; claude.ai live-verified on a `:443` endpoint 2026-07-21. Both docs passed a 3-lens adversarial review — 3 BLOCKs, ~25 findings folded, incl. the draft's own wrong revocation claim). *(This line still read "Proposed" until 2026-07-24 — it was never updated when the unit merged, which is exactly the drift the docs-reconcile rule exists to prevent.)* · **Date:** 2026-07-17 · **Context:** issue #47. This repo has recorded the deviation honestly since V0: "the MCP auth spec expects HTTP transports to be OAuth 2.1 resource servers; V0's static bearer is a deliberate, wire-compatible deviation — strict clients may reject a plain bearer." Beta (~Aug) puts the product in front of exactly those strict clients. A 2-track recon (code + live-web, 2026-07-17) established the facts below; the original "#47 = metadata + expiry" framing was WRONG and this ADR records why.

## The recon facts that decide the shape (cited; do not re-litigate without newer evidence)

1. **Metadata alone is non-compliant AND unlocks nothing.** Current spec (2025-11-25): an HTTP MCP server supporting auth MUST serve RFC 9728 protected-resource metadata, and that document MUST name at least one authorization server (modelcontextprotocol.io/specification/2025-11-25/basic/authorization). A PRM with no real AS behind it advertises a flow that cannot complete.
2. **Both target clients require a real OAuth flow.** claude.ai custom connectors: OAuth (DCR out of the box; CIMD; pre-registered creds) or none — the `static_headers` API-key option is an invite-gated beta and the public request for a key field was closed "not planned" (claude.com/docs/connectors/building/authentication; github.com/anthropics/claude-ai-mcp #112). ChatGPT developer-mode: "No Authentication", "OAuth", "Mixed" — no key field at all (developers.openai.com/api/docs/guides/developer-mode). **The only self-serve path that unlocks BOTH is running a minimal authorization server.** Prior art abounds: Cloudflare workers-oauth-provider, @mcpauth/auth, hand-rolled five-endpoint ASes verified against claude.ai; Cloudflare's own guidance states the static bearer is security-sufficient and the OAuth layer exists for client compatibility.
3. **Serving discovery can BREAK currently-working clients.** ADR 0024 recorded that bearer-header clients work today precisely because no OAuth well-knowns are served, and names a Cursor bug that ignores configured headers once discovery exists. Hence: **opt-in, default off, byte-identical when off.**
4. **Reachability is the honest limiter, not auth.** claude.ai egresses from 160.79.104.0/21; ChatGPT from OpenAI's cloud — a tailnet-private gateway is unreachable to them regardless of auth. The bridge is necessary-but-not-sufficient: it works WHEN the user opts into public exposure (Funnel, ADR 0024's documented opt-in tier). The zero-public-exposure beta promise (ADR 0025) is untouched — the bridge makes the opt-in path WORK, it does not make exposure the default.

## Decision

1. **Build the bridge, not the fig leaf:** a same-origin OAuth 2.1 AS on the MCP edge — PRM (both well-known paths) + RFC 8414 metadata (S256 advertised, public clients) + DCR + `/authorize` + `/token` (code + rotating refresh) + `WWW-Authenticate` on 401s. Same-origin with conventional paths deliberately dodges the observed claude.ai bug of hardcoding `/authorize` on the MCP base (claude-ai-mcp #82).
2. **The pasted agent key IS the login.** The authorize page validates the operator's existing Console-minted key via the same `resolveBearer` path and issues short-lived tokens mapped to that `agent_grants` row. No second identity, no new permission model, no consent UI (sectors are the consent, set in the Console); revocation and audit flow through the same row; the bridge stores only hashes and never the key.
3. **Opt-in via ONE var, fail-closed origin (deliberately no separate flag):** setting `MCP_PUBLIC_URL` IS the switch (the PRM `resource` must exactly match the user-typed URL; Host-derivation is spoofable and the code precedent — `canonicalBaseUrl` — already refuses it). Off = today's edge, byte-for-byte (the Cursor guard, §3 above).
4. **Bearer expiry joins the model as a first-class, optional lifetime:** `agent_grants.expires_at` (null = never, default — no silent change), enforced in `resolveBearer` AND per-call via the session cache (closing the recon-flagged mid-session gap for expiring credentials); Console mint gains presets + an active-row rotate (the existing atomic upsert-mint, surfaced); bridge access tokens are short-lived (3600s) with rotating refresh per the spec's public-client MUST.
5. **Grant lifecycle governs derived credentials — always (review-driven; the draft got this wrong).** Revoke is an UPDATE (the row survives), so FK cascades never fire on it: bridge-token resolution JOINS the grant row and denies on `revoked_at`/`expires_at`; `/token` re-reads the grant on BOTH grants (`invalid_grant` when revoked/expired); refresh lifetime is capped by key expiry (a refresh chain can never outlive its key); and **rotation deletes the grant's bridge codes+tokens in the same transaction** — rotation is the compromise response, and derived credentials die with the key. Only `DELETE /api/agents` relies on the FK cascade.
6. **Ship minimal abuse bounds in-unit rather than deferring an unauthenticated public write surface to #48:** a hard DCR client cap + per-IP buckets on register/authorize + a throttle on initialize-denial audit rows (an exposed edge's bot noise must not flood the append-only audit_log). #48's full edge hardening supersedes these; silence would not have been a decision.
7. **The authorize page defends the operator, not just the protocol:** frame-denial headers, bound single-use CSRF, and a MANDATORY display of the requesting client's name + redirect destination host — unauthenticated DCR means anyone can register a client and lure the operator to their own gateway's authorize page; showing "this approval sends a sign-in code to claude.ai" is the one defense the human can actually exercise. This display is anti-phishing, not consent UI (the no-consent-UI deferral stands).
8. **Deliberate deferrals:** CIMD (URL-shaped client_ids = SSRF surface; DCR satisfies both clients today) · `static_headers` (invite-gated, unplannable) · consent/scope UI (see §7's carve-out) · the hosted multi-tenant AS (unchanged, deferred chapter — the working notes gain the "minimal single-tenant bridge is in V0" qualifier at merge). Forward-compat noted: the 2026-07-28 spec RC (iss binding, RFC 9207) — the bridge sends `iss` from day one and keeps a stable issuer.

## Consequences

- The working notes' strict-client caveat paragraph AND their deferred-AS sentence are rewritten at merge; ADR 0024's and the runbook's "only /mcp exists by construction" sentences are qualified; the runbook gains the enable+Funnel verification procedure. Tracked under #47.
- #48 (hardening) inherits the bridge's unauthenticated endpoints for FULL rate-limiting and audit_log retention; the unit's own minimal caps (§6) are explicit stopgaps.
- The live acceptance matrix requires a temporary, reverted Funnel exposure on a real deployment — a human-assisted step, recorded in the PR.
- Three new control-plane tables (`oauth_bridge_clients` / `oauth_bridge_codes` / `oauth_bridge_tokens` — codes are rows, not memory, so a mid-flow restart survives) with GC that is hygiene-never-revocation (deadness is enforced at the expiry instant regardless of row retention); `agent_grants` gains its first new column since baseline (`expires_at`).
- The audit trail gains initialize-time denials (previously entirely silent) and token issue/refresh events — a forensic improvement independent of the bridge; `AccessDenied` gains a distinct `reason` field, ending the reason-in-sector conflation on both audit paths.
- Coordination debt recorded: the memory-floor unit and this one both edit `src/mcp/server.ts` + the `AuditTool` union and both queue a migration number — merges are serialized and the later migration renumbered.
