# ADR 0025 — Poll cadence is a user setting; provider webhooks are a post-beta public tier

**Status:** Accepted (decided 2026-07-10) · **Date:** 2026-07-11 · **Context:** beta ships next month with the promise "works fully with ZERO public exposure" (ADR 0024); finance/health freshness was a hardcoded 6h.

## Decision

1. **Per-connection cadence, user-set, connector-bounded.** `connectors.sync_interval_sec` (migration 0012, nullable — null = the connector default, so an untouched install behaves exactly as before). `effective = clamp(override ?? default, floor: policy.minIntervalSec)` computed in ONE exported helper (`effectiveIntervalSec`) consumed by the scheduler timer, `next_sync_at`, and both freshness call sites — the actual rhythm, the displayed expectation, and the staleness judgment cannot disagree. **The rule extends to the scheduler's skip-gate** (`effectiveToleranceSec = min(policy.freshnessToleranceSec ?? effective, effective)`) — found as a review BLOCK: without it, a faster override fired timers that silently did nothing until the connector's static tolerance elapsed.
2. **Floors are connector policy with cited evidence**, because the constraint belongs to the source: Plaid 900s (per-Item monthly billing, calls free; 50/min rate limit), SimpleFIN **7200s** (the bridge expects ≤24 requests/day and disables tokens beyond warnings — 12/day leaves half the budget for sync-now/fetch_live; bridge data refreshes ~daily), WHOOP 900s (100/min, 10k/day), Microsoft/Gmail/Google 300s (far inside Graph/IMAP/quota limits). Absent floor → the default IS the floor (slow-down only).
3. **Three-layer enforcement, no layer load-bearing:** Console offers only ≥-floor presets → the API rejects below-floor with a typed 400 naming the field and the floor (never a silent clamp of explicit input) → the scheduler clamps at read time (a hand-edited row cannot hammer a provider). Upper bound **14 days** — an anti-typo guard that is also hard-required: Node timers overflow at 2^31−1 ms (~24.8 days) and a larger interval fires every ~1 ms (empirically verified in review); the scheduler additionally clamps every timer delay to 2^31−1 ms as a belt.
4. **The webhook tier is POST-BETA, opt-in, public-tier.** Plaid `SYNC_UPDATES_AVAILABLE` (+ ITEM health events: `PENDING_EXPIRATION`/`ERROR`/`USER_PERMISSION_REVOKED`) would give near-realtime, but Plaid's cloud must POST to a publicly reachable URL — impossible tailnet-private, and the beta promise stays zero-public-exposure. Design sketch recorded for when it comes: a dedicated JWT-verified route (`Plaid-Verification` header + `/webhook_verification_key/get` — the generic ingest secret-header model does not fit), per-Item registration (link-token for new Items, `/item/webhook/update` for existing), ADR-0008 ping-then-pull (the webhook is a doorbell; `syncConnection` stays the only write path), relaxed fallback poll on webhook-registered Items. Faster polling delivers minutes-behind freshness today with zero exposure; a doorbell-relay pattern (the webhook body carries no data) is documented as a user option, not built.

## Consequences
- The Console's connection detail gains the cadence card (poll connections only); non-poll connections 409 at the API and render no picker — cadence is not ours to control for push-stream (instant) or device-push (the phone decides).
- Review-noted residual: a hand-edited row beyond the 14-day API bound syncs at the ~24.8-day timer ceiling while freshness advertises the stored interval — bounded, provider-safe, API-unreachable; accepted.
- The wave-12 "Plaid webhook" backlog line is superseded by §4's tiering.
