# ADRs — the decision record

An ADR here is a numbered, dated record of a decision that **binds the build**: the shape that was chosen, the alternatives that were rejected, and the reasoning that got there — written so a later agent doesn't re-derive it, and doesn't quietly reverse it.

They are **decisions with rationale, not tutorials.** An ADR tells you *why* the code has the shape it has and what you may not change without a new decision; it does not tell you how to use it. For how-to, go to the setup guide (`docs/SETUP.md`), the runbooks (`docs/runbooks/`), and `CONTRIBUTING.md`.

**Status is reproduced verbatim from each file, capitalisation included** — this index never normalises one word into another. A **Proposed** ADR is **not yet binding**: its decision is still a draft, so do not cite it as settled law. A file's status line records the decision's own state and may lag the code that implements it.

The one-liners below are routing bait, not the decision. When a trigger in the last column fires, open the ADR.
