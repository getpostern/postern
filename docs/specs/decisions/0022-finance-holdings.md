# ADR 0022 — finance.holding: queryable holdings from both providers, snapshot-tombstone reconcile, symbol-keyed dedup

**Status:** accepted (2026-07-02) · **Issue:** #36 · **Extends:** ADR 0004 (tombstones), ADR 0021 (finance dedup)

## Context
Both finance providers know what the user holds, but the gateway served none of it: SimpleFIN delivered holdings buried in `finance_accounts.raw.holdings[]` (unqueryable), Plaid investments were never fetched, and ADR 0021 explicitly scoped holdings OUT of the dedup cluster. For brokerage/retirement users — where most of the money is — "what do I hold?" returned a bare account balance. A lossless-gateway violation.

## Decision
1. **Third finance object.** `finance_holdings` on the standard domain template (migration 0010) + REGISTRY `finance.holding` (`primaryTime: as_of`, `serveDeduped: true`). Neutral floor = `symbol`/`name`/`quantity`/`market_value`/`cost_basis`/`currency`/`as_of` (+ `account_source_id` linkage); `security_type` is the Plaid-filled enrichment column; tax lots, ISINs/CUSIPs, vesting, prices stay in `raw`. **No price column** — Plaid reports current price, SimpleFIN average purchase price; a column whose meaning depends on the provider is the lie the floor exists to prevent (agents derive `market_value/quantity`).
2. **Snapshot-tombstone reconcile.** Holdings are a snapshot, not an event stream; both providers deliver the full set per sync. New generic helper `reconcileObjectSnapshot(connectionId, sector, object, liveSourceIds, startedAt)` in the runner (HA's fence semantics generalized: rows upserted this sync survive; prior rows absent from the live set are tombstoned; resurrect-on-upsert per ADR 0004). Connectors call it **only after a COMPLETE enumeration** — never on a skipped/failed fetch — and SimpleFIN additionally requires the payload's `errors[]` to be empty (a partially-failing bridge must not mass-tombstone a bank's holdings).
3. **Plaid billing gate (option a).** Plaid bills investments per-Item once initialized; the product auto-adds to existing Items on first call (no re-link). The connector calls `/investments/holdings/get` ONLY for Items whose synced accounts include an `investment`-type account — connecting a brokerage IS the opt-in; an Item without investments is structurally unbillable. `PRODUCTS_NOT_SUPPORTED`/`NO_INVESTMENT_ACCOUNTS`/`PRODUCT_NOT_READY` are benign per-Item skips. **Investment transactions stay OUT** (decided): their separate Plaid subscription starts on the first `/investments/transactions/get` call, and wiring them forces reworking the credit+depository txn-dedup restriction — own follow-up when wanted.
4. **Symbol-keyed holdings dedup (superseding "dedup later").** Within an account dedup group (ADR 0021 already proves "same real account"), the same normalized non-empty symbol = the same holding: 3-row synthetic union (`union:holding:<inst>:<mask>:<SYMBOL>`, `raw=null`), reals shadowed, `quantity`/`market_value`/`cost_basis`/`as_of` co-selected as ONE tuple from the freshest-`as_of` member (the balance-tuple rule), rest best-per-field. **Fail-open guards:** empty-symbol rows (cash, ticker-less bonds/options) never merge; an intra-connection same-symbol collision marks the bucket ambiguous; no name/identifier-crosswalk matching.
5. **Review-fold hardening (from a BLOCK ×3, independently repro'd).** The sweep excludes the engine-reserved **`union:%`** soid namespace — without it, the anchor connection's next sync tombstoned the dedup winner and the zombie's unique key froze ALL finance reconcile. All three passes' synthetic CREATEs (holdings + the same latent pattern found in accounts AND transactions) now share a resurrecting `upsertSynthetic()` (recompute-on-conflict, `deleted_at=null`, stable id), which also defends a malicious provider planting reserved-namespace soids.

## Consequences
- `get_schema("finance")` returns three objects; `sum(market_value) groupBy security_type` etc. work; a doubly-connected brokerage serves each position once.
- Documented residuals: a Plaid transient-partial-accounts snapshot can tombstone holdings for one cadence (self-heals by resurrect; no detectable signal to guard on); benign-skip matching is substring-over-controlled-format; SimpleFIN `as_of` is null when `created` is absent (normalize stays pure; nulls sort first in the default desc order).
- Hardening fast-follows (filed, non-blocking): tombstone-inclusive marker reset for the TRANSACTION pass (holdings got it; txn markers on tombstoned rows are inert but stale); DROP/GC for a tombstoned synthetic whose group dissolves (post-fix unreachable by the engine itself); an ingest-side guard rejecting provider soids in the reserved `union:%` namespace (today a provider can plant an immortal forged row on its own connection — no privilege boundary crossed). **All three CLOSED 2026-07-09 by the #37 batch:** txn AND accounts passes got tombstone-inclusive resets, a hard-DELETE GC after each pass's DROP diff reaps dissolved tombstoned synthetics (counted into `dropped`), and `applyRecords` rejects `union:%` on both the live and deletion branches (HA's self-managed writes skip-with-warn). Known residual (security-review LOW, pre-existing class): a tombstoned union zombie whose group is STILL desired but sits on a non-anchor connection survives the soid-keyed GC; near-unmintable post-guard, follow-up would key the GC on (connection_id, soid).
- Holdings-level cross-provider dedup for accounts NOT in any dedup group does not exist (by design — the account group is the anchor).

**Residual CLOSED (2026-07-11, unit `finance-dedup-trust-batch`):** all three reconcile GC sweeps now key on the `(connection_id, source_object_id)` PAIR of desired synthetics — the non-anchor tombstoned-zombie edge (and its worst case, the recompute-collision rollback that froze all finance dedup) is test-proven impossible.
