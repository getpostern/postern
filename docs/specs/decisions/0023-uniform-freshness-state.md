# ADR 0023 — Uniform freshness state: two clocks, exceptions-only words, one server-side derivation

**Status:** Accepted · **Date:** 2026-07-10 · **Closes:** #39, #40 · **Display grammar:** `docs/design/freshness-grammar.md` · **Born from:** the 2-week invisible HA outage (Jun 25 → Jul 9, 2026 — a dead push stream rendered "Live" everywhere while every health check answered ok).

## Decision

1. **Two clocks, never conflated.** Transport freshness (`connectors.last_synced_at` — when did we last hear from the source; stamped by every mode) is a different fact from data recency (each REGISTRY object's `primaryTime` — what period the content covers). UI and agent surfaces never present one in the other's slot.

2. **Push-stream health is PERSISTED, in columns, not a status value.** Migration 0011: `connectors.stream_state` (`connected|retrying|down`, null for non-stream), `stream_error` (masked), `stream_changed_at` (stamped on state TRANSITIONS only). Written by `markStreamState` (never touches `status` — the pause/revoke guard holds by construction) at every transition: bootstrap start-retry, the HA WS client's own mid-run reconnect loop (new `onUp`/`onDown` hooks), and the previously-SILENT mid-run auth death (`failAuth` on a re-auth now fires `onDown` and the connector writes `down` + `status='error'`). Columns-not-status because `status` is load-bearing in the scan (`active|error`), ingest (`active`), and describe filters — a new enum value would have rippled through all of them.

3. **One derived state, computed in exactly one place** (`src/core/freshness.ts`, pure, injectable clock): `ok | syncing | stale | unreachable | error | paused | disconnected | never_synced`. Deliberately NO `live`/`fresh` split — transport mechanism is not a health state (a quiet-house stream with an old last-event and an open socket is healthy, which a recency word can't express and a "Live" badge lied about for two weeks). Healthy renders as the bare timestamp, no badge; state words are for exceptions. Mapping: row `status` wins outright (revoked→disconnected, paused, error, syncing); active push-stream reads `stream_state` (connected→ok; retrying/down→unreachable; null → 15-min age fallback `PUSH_STREAM_STALE_MS`); active push-webhook is advisory-only (`WEBHOOK_STALE_MS` 48 h; NEVER unreachable — the device makes no promise; display "Device controlled", never a predicted next-time); active poll staleness = 1.5× the connector's `defaultIntervalSec` (`POLL_STALE_FACTOR`). `next_expected_at` is real for poll, null-with-meaning for both push kinds. Severity (worst-first, total over the enum): `error > unreachable > stale > syncing > never_synced > paused > disconnected > ok` — `disconnected` ranked between `paused` and `ok` (build-time pin; a revoked row is quiet, not alarming).

4. **The tuple `{state, last_heard_at, next_expected_at, stream_state, error}` is served identically by all four surfaces:** `GET /api/connectors` (`ConnectorStatus.freshness`), `describe_context` (per connection — and the WHERE widened to `active|error|syncing|paused` so an unhealthy connection is VISIBLE to agents instead of vanishing; revoked stays out), operator `sync-now` (push branch answers from the persisted stream truth: dead → `ok:false` + masked error + audit `error`; the retry loop is the probe — no ad-hoc pings), and sector `fetch_live` (additive per-connection `connections[]`; a down stream forces `synced:false` with an attributed error). The Console renders the server's word through ONE shared mapping (`apps/web/src/api/freshness.ts`), retiring three divergent FE derivations; the `live` pill kind is no longer emitted for connection health.

## Consequences / accepted residuals (all review-noted, none blocking)

- Mid-run-terminally-dead push client is now VISIBLE but not auto-restarted (bootstrap's `tracked` never re-attempts a started entry) — follow-up filed.
- Bounded honesty gaps: a crash/shutdown writes no `down` (rows read `connected` while the gateway is off; corrected at next boot scan); a drop in the start()-to-stamp window can leave `connected` for ≤1 backoff tick.
- Transitional FE nit: an unstamped push-STREAM row (pre-first-start) captions "Device controlled" until B1 stamps it (first boot after deploy).
- Also noted for follow-up: `markSyncing` shares the pre-existing unguarded-status class (markError got the guard at merge); bootstrap's stderr line prints the unmasked start-failure message (DB write is masked); `describeContext`'s broad legacy catch would blank the whole list if a per-row derivation ever threw; the `toStatus` intervalSec wiring lacks a dedicated test.
- Thresholds (15 min stream fallback / 48 h webhook advisory / 1.5× poll) are constants, not config — revisit only with evidence.

**Postscript (2026-07-11, unit `push-restart-residuals`, #41):** the recorded residuals shipped — a mid-run-terminally-dead push client now auto-restarts when (and ONLY when) its credential or instance URL materially changes (the auth no-hammer rule is preserved: an unchanged dead token stays visibly dead; pause→resume and re-paste remain the manual hatches); the `markSyncing`/success-write-back/ingest-write-back writers gained the `markError`-pattern paused/revoked guard; the bootstrap stderr retry line is masked; `describeContext` degrades a failing row instead of blanking the list; the `intervalSec` derivation is mutation-pinned; and the Console captions render a served `push_kind` (webhook = "Device controlled", stream never, paused = no next line).
